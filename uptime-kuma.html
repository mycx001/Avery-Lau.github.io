基于 Docker 快速搭建私有 Uptime Kuma 运维监控面板与多渠道告警实战

作者: Avery | 分类: 云原生与自托管 | 最后更新: 2026-11

在运维多台云服务器、自建中转或托管个人博客时，业务服务何时故障宕机、网络何时发生大面积丢包，运维人员必须能在第一时间获知。开源界备受好评的 Uptime Kuma 提供了不输商业级产品（如 UptimeRobot）的监控能力，且完全免费、数据自持、原生支持精美的公开状态页与多渠道自动告警。

一、 架构需求与基础设施选型

Uptime Kuma 占用资源极小（512MB 内存即可轻量跑起），支持 HTTP(s)、TCP 端口、Ping、DNS 记录、SSL 证书有效天数以及 Docker 容器健康度等多种探针检测。

💡 为什么“监控服务器自身”必须极度稳定？

监控节点的职责是充当守门人。如果监控机自身的硬件频繁被超售抢占、宿主机网络经常抖动丢包，系统就会产生大量假警报，失去监控的实际意义。因此，用于部署监控守护进程的 VPS 必须具备极高在线率（SLA）以及优秀的公网连通性。

二、 使用 Docker Compose 快速部署 Uptime Kuma

1. 准备配置目录并编写 Compose 文件

# 创建挂载与持久化目录
mkdir -p /opt/uptime-kuma && cd /opt/uptime-kuma

# 编写 docker-compose.yml
cat > docker-compose.yml << 'EOF'
version: '3.8'

services:
  uptime-kuma:
    image: louislam/uptime-kuma:1
    container_name: uptime-kuma
    restart: always
    volumes:
      - ./data:/app/data
    ports:
      - "3001:3001"
EOF

2. 启动容器服务与防火墙放行

# 后台拉取镜像并启动
docker compose up -d

# 检查容器运行状态 (看到 Up 状态即正常)
docker ps | grep uptime-kuma

# 放行 Uptime Kuma 面板默认端口 (若使用反向代理则仅需放行 80/443)
ufw allow 3001/tcp

三、 初始化管理员账户与配置首个监控项

  1. 在浏览器访问 http://你的服务器IP:3001。
  2. 初次进入时，按提示设置管理员用户名和密码。
  3. 点击左上角的 “添加新监控项（Add New Monitor）”：
    • 监控类型（Monitor Type）： 常用包括 HTTP(s)（用于监控网站或API）、TCP Port（监控SSH或特定服务端口）、Ping（监控主机连通性）。
    • 易记名称（Friendly Name）： 例如 核心API生产节点 或 香港业务中转机。
    • 心跳间隔（Heartbeat Interval）： 推荐设置为 60 秒（轮询过于频繁容易给被监测端造成网络压力）。
  4. 点击保存，等待第一次检测变绿（状态显示为 Up）。

四、 配置 Telegram / 邮件 / Webhook 故障自动告警

Uptime Kuma 原生集成了数十种通知渠道。以最常用的 Telegram Bot 告警为例：

# 告警配置流程：
1. 在面板右上角点击 "设置 (Settings)" -> "告警通知 (Notifications)"。
2. 点击 "设置告警 (Setup Notification)"，选择 "Telegram"。
3. 填入你的 Telegram Bot Token 和接收消息的 Chat ID。
4. 点击 "测试 (Test)"，若手机收到测试消息，勾选 "默认启用"，点击保存。
进阶技巧： 可以在面板顶部点击 “状态页面（Status Pages）”，一键定制专属的公开服务健康看板（支持自定义域名与 Logo），供团队成员或客户随时查看基础设施实时在线情况。
